## 3. 가설

### H1 [점수] invsqrt 를 데이터플로부터 다시 짜서 Q ≤ 61 로 만든다

- **가설**: 공개 계보의 scratch 40 은 할당 문제가 아니라 데이터플로 (가장 넓은 단계의 정밀도·보관 방식) 가 정한 값이다. 가장 넓은 단계를 재계산 또는 측정 기반 해제로 바꾸면 scratch ≤ 39, C 증가 ≤ 25 (1 qubit 환율) 인 회로를 만들 수 있다. 목표는 Q 61 에 C ≤ 1,560, 비용 ≤ 95,160 (−2.65%) 이다.
- **근거**:
  - 비용 97,747 = 62 × 1,576.6. LP 와 peephole 은 포화됐다 (r002, r003, r020). 40개가 연산의 37% 구간에서 동시에 살아 있다 (r005, r022) → 할당으로는 0.
  - static Toffoli 류 1,519 (CCX 1,183 + CCZ 135 + CSWAP 201) 인데 평균은 1,281 이다. 238 은 HMR 조건부 실행으로 이미 아낀 것이다. HMR 899, 조건 블록 314개 (조건 안의 Toffoli 334). 회전은 q28 (`outputs/research/inv_ops.txt` 15281–15619 줄) 과 q50 (25824–26064 줄) 에 비트 직렬로 몰려 있다. CSWAP 201 은 정규화 시프트로 보인다 (미검증).
  - 존재 증거: 22.68 → 비용 91,569 = Q58×C1579 또는 Q61×C1501 또는 Q62×C1477 (어느 쪽인지는 모름).
- **메커니즘**: tol(x) = 2^-24/√x 이므로 상대 정밀도만 필요하다. 1 qubit 의 가치 (C 25.4) 가 25비트 덧셈 하나를 다시 계산하는 비용 (Toffoli 약 25, 측정 해제 시 절반) 과 비슷하다. 따라서 가장 넓은 구간에서 한 레지스터를 "보관" 대신 "필요할 때 재계산" 하거나 HMR 로 해제했다가 위상 보정으로 처리하면 qubit 1개를 C 25 미만에 바꿀 수 있다. 재계산이 측정 기반 해제 (조건부 50%) 와 맞물리면 평균 Toffoli 증가는 더 작다.
- **가장 강한 반론**:
  - (a) 2,500팀이 보는 과제인데 공개 계보는 63→62 이후 Q 62 에 멈춰 있다.
  - (b) 병목 x 에서 오차가 tol 의 90.6% (x=3.06M) ~ 99.9% (x=213) 를 쓴다. 정밀도 비트를 하나라도 빼면 바로 실패하므로 남는 길은 재계산뿐이다.
  - (c) 22.68 은 출처가 디스커션 글 하나뿐이고, Q 62 그대로 C −6.3% 일 수도 있다.
  - (d) 40개 동시생존 구간이 넓으면 (37%) 재계산 범위도 커져서 C 25 를 넘을 수 있다.
- **검증 방법** (H2 의 원장이 필요):
  1. 원장에서 가장 넓은 단계와 그때 살아 있는 값들을 특정한다.
  2. 설계 후보 3개 이상의 (Q, Toffoli 평균, 회전 수, eps) 해석 표를 만든다.
  3. 가장 유망한 안을 numpy 로 비트정확하게 전수 시뮬레이션해서 (x = 1..3,133,452, 수 분) max err/tol 과 여유를 구하고, 여유에서 eps 와 C 를 계산한다.
  4. kickmix 회로를 만들어 공식 verifier 로 확인한다 (로컬 131초, 빈 salt + salt 3개).
  - 자원: 로컬 M4 CPU, 2~3 밤.
- **채택**: 공식 PASS (salt 4개) 이고 Q·C ≤ 97,365 (−0.39%, 은 컷 수준) 이면 후보로 채택한다. Q ≤ 61 이고 C ≤ 1,560 이면 강한 채택.
- **기각**: 3번째 밤이 끝날 때까지 해석 표에 예측 Q·C ≤ 97,000 (−0.8%) 인 후보가 없거나, 최선 후보의 비트정확 시뮬레이션에서 err/tol > 1 인 x 가 나오고 qubit 당 C +25 안에서 고칠 수 없으면 기각한다. 넓이 하한을 숫자로 남긴다.
- **맞으면**: 같은 기법으로 Q 60 (GM +1.1%, 25.215, 약 56위) 을 시도한다. 수동 제출은 감독 판단으로 한다.
- **틀리면**: "C 감소형" (회전 41개 → 비트 수 축소, 정규화 시프트 비용 축소) 을 같은 원장으로 평가한다. 거기서도 −0.8% 가 안 나오면 invsqrt 를 닫고 H3/H5 쪽으로 간다.

### H2 [전진] invsqrt 공개 회로의 비트정확 데이터플로 모델 (원장)

- **가설**: 공개 invsqrt (Q62) 를 단계 (정규화, 초기값, 반복, 위상 kick, 역계산) 별 레지스터 의미, Toffoli, 생존 폭으로 재구성할 수 있다. 이 모델로 numpy 에서 계산한 x 별 최종 위상오차는 공식 verifier 와 2^-64 turn 단위까지 일치한다.
- **근거**: 47,882줄 `outputs/research/inv_ops.txt`, 생존 도구 (`src/qubit_liveness_sim.py`, `src/qubit_intervals.py`, `src/live_fine.py`), 회전 LP (`src/inv_angle_lp.py`, x 별 오차 캐시 `outputs/research/inv_lp_cache_y33.npz`).
- **메커니즘**: 지금은 변형 하나를 시험하려면 회로를 만들고 131초 verify 를 돌려야 한다. 모델이 있으면 변형을 전 x 에 대해 수 초에 평가하고, "어느 단계가 Q 를 정하는지" 를 숫자로 볼 수 있다. H1 의 2·3단계가 이 모델에 기대고 있다.
- **반론**: 4.8만 게이트에서 의미를 역추적하는 데 시간이 많이 들 수 있다. 처음부터 설계하는 편이 빠를 수도 있다.
- **검증 방법**:
  1. kickmix Simulator (공식 패키지) 로 무작위 x 1만 개를 돌리면서 단계 경계에서 레지스터 값을 스냅샷한다.
  2. 각 레지스터를 x 의 함수 (예: floor(2^k/√x), 정규화 지수) 에 맞춘다.
  3. numpy 모델로 전 x 오차를 재현한다.
  4. 단계별 Toffoli·폭 원장 표를 만든다.
  - 공개 노트북 코드는 실행하지 않는다 (회로 파일을 데이터로 시뮬레이션하는 것만 한다). 4~6시간.
- **채택**: 무작위 10^5 개 x 와 LP 활성 x 전부에서 오차가 verifier 와 일치하고, 원장의 Toffoli 합이 1,281.47 과 1% 안에서 맞으면 채택.
- **기각**: 6시간 안에 가장 넓은 단계의 레지스터 의미를 못 밝히면 역추적을 멈추고 H1 의 "처음부터 설계" 경로로 간다. 이때 비용 하한을 손계산한 표만 남긴다.
- **맞으면**: H1 2단계로 간다.
- **틀리면**: 위와 같다.

### H3 [전진] chem 형상 민감도를 연속 최적화로 측정한다 (재학습할 가치가 있는지 판정)

- **가설**: 자체 연속 (비양자화) 최적화기로 형상마다 "e1, e2 ≤ 0.017 (양자화 여유 3 mHa), E_gap > floor, Λ > 49" 를 만족하는 최소 λ 를 구한다. 그러면 C43/C42/C40/B135/B129 중 하나 이상에서 λ 증가가 비용모델 손익분기보다 0.4%p 이상 작게 나온다.
- **손익분기 (비용모델 `src/chem_shape_eval.cost_model`, C44 대비 T·Q)**:

  | 형상 | T·Q 비율 | 손익분기 λ 증가 |

  | C43 | 0.9948 | +0.52% |
  | C42 | 0.9896 | +1.05% |
  | C40 | 0.9792 | +2.1% |
  | B135 C44 | 0.9767 | +2.4% |
  | B129 C44 | 0.9592 | +4.25% |

- **근거**:
  - 공개 계보가 실제로 C45 (words 2d294ad0, tree 2f3b97, λ 46.875) → C44 (words e9502331, tree 665e63, λ 46.893) 로 재학습해 heuristic T −79 를 얻었고, λ 는 +0.04% 만 늘었다. 이는 손익분기 +0.52% 보다 훨씬 작다.

  - p01: 단어를 고정한 채로는 C 를 줄일 수 없다.
  - 공개 테이블마다 tree 가 다르다 (75ec34, 2f3b97, 665e63, 8f127f, e5cb00). tree 는 자유 변수다.
- **메커니즘**: 연속 최적의 λ 는 양자화된 λ 의 하한이다. 연속에서도 손익분기를 넘는 형상은 버린다. 남는 형상에서 손익분기와의 차이가 양자화·코딩 제약에 쓸 예산이 된다.

  - (b) 비볼록이라 시작점에 따라 결과가 달라진다.
  - (c) 공개 쪽이 이미 C 축을 훑었을 수 있다 (C44 에서 멈춘 이유가 있을 것).
- **검증 방법**:
