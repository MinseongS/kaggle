# 사용자 지시 누적

자동 실행 에이전트는 매 실행 **가장 먼저** 이 파일을 읽는다. 지시는 지워지지 않고 쌓인다. 뒤의 지시가 앞의 지시와 충돌하면 뒤의 것이 우선.

## 받은 편지함 (새 지시, 아직 반영 안 됨)
사용자나 대화 세션의 Claude 가 여기에 `- YYYY-MM-DD: 지시` 형식으로 추가한다.
에이전트는 각 항목을 DAILY.md 절차·QUEUE.md·도구에 반영한 뒤 아래 "반영됨" 으로 옮기고, 어디에 어떻게 반영했는지 적는다.
절대 규칙(DAILY.md "절대 규칙")을 바꿔야 하는 지시는 반영하지 말고 리포트에 "사용자 확인 필요"로 올린다.

- 2026-11-07: "공개노트북 위주로 하면 안돼. 직접 데이터를 수집하고 내가 세운 가설이 맞아야하고 그렇게 해야 의미있는 점수와 등수를 받을수있어." → 점수 개선의 주 경로는 **직접 수집한 데이터 + 우리가 세운 가설의 검증**이다. (1) 실험·제출마다 먼저 가설 1줄(무엇이 왜 좋아질지, 예상 CV 변화)을 쓰고, 결과로 맞았는지 판정해 EXPERIMENTS 메모에 남긴다. (2) 공개 노트북은 기준점·참고로만 쓴다. 공개 노트북을 그대로 재현하거나 손잡이만 바꿔 내는 제출은 개선 작업으로 치지 않으며, 하루 제출의 주 용도가 되면 안 된다. (3) 대회 규칙이 허용하는 범위에서 데이터를 직접 수집·생성(외부 데이터 허용 여부는 규칙에서 먼저 확인)하고, 무료 자원(로컬 M4, Kaggle 무료 GPU)만 쓴다. (4) 판정은 로컬 CV/verifier가 우선이고 LB는 확인용. 이전 지시 중 공개 노트북 흡수를 주 경로로 둔 항목은 이 지시가 우선한다. (exp014 등 공개 0.480 fork는 기준점으로만 두고, 가설 기반 자체 개선을 QUEUE 상위로)
- 2026-11-07: "오늘 건 멈추고 가설도 직접 세우면 돼. 가설 세우는걸 신중하게 해야해. 진짜 유의미한 가설과 앞으로 가기위한 가설. 이전의 모은 정보를 토대로 논리적이고 치밀하게 세워야해." → 가설은 에이전트가 세우되 `HYPOTHESES.md` 에 근거(이전 실험·리포트의 구체 수치)·예상 효과·검증 방법·기각 조건과 함께 쓴다. 점수에 실제로 영향을 줄 규모의 가설, 다음 단계로 나아가게 하는 가설만 올린다 (손잡이 미세조정·공개 재현은 가설이 아님). 새 가설을 추가하거나 고칠 때는 기존 기록을 다시 읽고 논리를 점검한 뒤 쓰며, 실행은 HYPOTHESES.md 의 우선순위를 따른다.
