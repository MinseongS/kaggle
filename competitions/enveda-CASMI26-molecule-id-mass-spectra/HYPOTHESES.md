### 1.5 sim2 가 LB 부호를 못 맞힌 이유 (코드로 확인)
1. **지표의 범위가 다르다.** sim2 가 잰 것은 PubChem 채널 단독 MRR@25 이다. 그것도 "정답이 tier 에 있고, 정답 행을 pass2 에 강제로 넣은" 조건부 값이다(`sim2_gen_src.py` 머리말 "+ every truth row"). 실제로는 정답의 30% 가 pass1 2000위 밖이다.
2. **최종 층이 2~25위를 다시 정렬한다.** 0.480 노트북 cell 18 `pxm_merge` 는 2~25위를 `1/(3+기준순위) + 0.75/(3+신경망순위) + 0.10·pop/20 + 0.05·spec + 0.02·np` 로 재정렬한다. 그래서 채널 내부 순서는 "기준 순위" 항으로만 남는다. sim2 이득의 대부분은 정답을 채널 안에서 몇 칸 올린 것인데, 이 부분은 최종 리스트에서 대부분 사라진다.
3. **채널이 닿는 분자가 적다.** 채널은 lib_max<0.9 이고 정답이 pool 밖인 분자(②-PC, 약 6~12%)에서만 의미가 있다.
4. **문서로 남은 전이율.** 1위 결정 쪽은 panel dbdrop 승격 +0.16 이 LB +0.024 이상으로 이어졌다(전이율 약 0.15~0.25). 채널 순서 쪽은 panel 0.51→0.95(+0.44)가 LB +0.004 에 그쳤다(EXPERIMENTS panel-stack 메모, 원출처는 확인 못 함). 전이율이 약 0.01 이다. 같은 비율이면 exp016 의 sim2 +0.039 는 **LB +0.0004~0.004 로 예측**되고, 실제 −0.006 은 노이즈와 맞는다.
5. **"게이트는 그대로"가 아니었다.** poplam20/20b 는 승격 판정 기준(S 는 λ0.15, `S>6 & pop≥5`)을 유지했다. 하지만 판정 대상인 `pc[0]` 은 새 정렬의 1위라서 **판정받는 후보 자체가 바뀐다.** [probe] sim2 에서 새 정렬 1위의 평균 pop 은 8.39(공개) → 9.48(e15) → 10.08(e16) 로, 더 유명한 후보가 판정을 받는다. 승격이 늘었는지는 sim2 의 z 스케일이 실제와 달라 잴 수 없다(sim2 S>6&pop≥5 발화 2.7% vs 노트북 주석 "S 중앙값 ~6").
6. pool 제외 차이는 원인이 아니다. 실제 채널은 pool 구조를 뺀다(`k in _W['pool_keys']: continue`). sim2 행의 11% 가 pool 성격(train 구조 또는 NP 카탈로그)이다. [probe] 이를 빼도 e15/e16 은 +0.044/+0.070 이라 부호는 그대로다.
7. `sim2-testmass` 서브셋과 `select.py` 의 질량 분포는 보이는 test.parquet 기준이다. 그런데 호스트는 보이는 test 가 **train 에서 뽑은 예시**라고 밝혔다(research/02). 숨겨진 test 분포라는 근거가 없다.

**결론**: sim2 가 틀린 게 아니다. **최종 점수와 거의 무관한 하위 지표를 정밀하게 잰 것**이다. se 0.003 은 sim2 지표의 정밀도이지 LB 효과의 정밀도가 아니다. DAILY 의 "CV 통과 = bootstrap se 1배" 기준은 하위 지표에서는 거의 모든 것을 통과시킨다.

## 3. 가설

종류: **전진 가설**은 측정 도구나 방향을 정하는 가설이고, **점수 가설**은 점수를 직접 올리는 가설이다.

### H1 (전진) 최종 리스트 단위 하네스: FL-replay
- **가설**: 공개 파이프라인의 라우팅(lib_max<0.9), 5칸 병합, 1위 승격, 2~25위 재정렬을 sim2·panel 분자에 재생해 최종 25개 리스트의 MRR 로 재면(FL-replay), exp015/016 의 Δ 는 |Δ| < 0.005 로 나온다. 또 문서로 남은 PubChem 경로 LB 변화 중 크기가 0.011 이상인 것들의 부호를 모두 맞힌다.
- **근거**: 1.5 의 1~5. 소급 검증에 쓸 라벨은 다음과 같다.
  - 승격 도입 +0.024 이상 (cell 43 주석)
  - aggressive gate 해제 −0.013 (0.480 노트북 cell 2)
  - exp015 −0.004, exp016 −0.006
  - pop prior 도입 +0.004 (출처 확인 필요)
- **메커니즘**: LB 는 최종 리스트로 계산된다. 변경이 최종 리스트를 바꾸는 분자의 비율과 위치(1위인지 2~25위인지)가 효과를 정한다. 그러니 이 둘을 재현하는 지표만 LB 를 예측할 수 있다.
- **예상 효과**: 점수에 직접 주는 효과는 0 이다. 대신 무의미한 제출(exp015/016 같은 것)을 막고, H2·H4 를 판정할 도구가 된다.
- **가장 강한 반론**:
  - 최종 층의 핵심 입력(엔진 1 leader, 신경망 scorer 순위, fragment check)은 train 전체로 학습된 공개 모델에서 나온다. 그래서 proxy 분자에서 정직하게 재현할 수 없고, 근사(bracket)만 가능하다.
  - 소급 라벨은 서로 다른 base 위의 단일 제출이라 각각 ±0.016 노이즈를 갖는다. 0.011 이상인 사례가 2~3개뿐이라, 부호를 다 맞혀도 우연일 확률이 1/4~1/8 이다.
  - ②-PC 와 ②-pool 의 비율을 모른다.
- **검증 방법**:
  1. **sim2 v2** (Kaggle CPU 약 2.5h, GPU 0):
     - 공개 `probe_one` 과 똑같이 만든다: PC_N1=5000 + pop union 200, z 는 pass2 집합 기준, pool_keys 제외.
     - 정답을 pass2 에 강제로 넣지 않고, 실제로 들어갔는지만 기록한다.
     - 분자마다 `promotion_evidence`(S, pop, raw_fz), 채널 1·2위 margin, n_window 를 내보낸다.
  2. **FL-replay** (로컬 6~8h): 세 시나리오를 섞는다.
     - (A) 정답 pool 안: panel nospec 리스트 + 주 리스트 1위 정답률 p_main 을 파라미터로 sweep
     - (B) 정답 PubChem 에만: sim2 v2 + panel dbdrop
     - (C) 정답 없음: 0점, 단 오승격 비용 없음
     - 비율은 1.3 추정값 주변에서 sweep 한다 (B 5~15%, A 30~40%).
     - 2~25위 재정렬은 두 극단으로 bracket 한다: "재정렬 없음" / "채널 후보의 기준 순위만 반영".
  3. 소급표: 위 라벨 4~5개를 재생해 부호와 크기를 비교한다.
- **채택/기각 기준**:
  - 채택: (i) exp015/016 예측 |Δ| ≤ 0.005 (bracket 양 끝 모두), (ii) |LB Δ| ≥ 0.011 인 사례의 부호가 모두 일치, (iii) 혼합비 sweep 전체에서 (ii) 의 부호가 유지.
  - 기각: (ii) 가 하나라도 틀리거나, exp015/016 예측이 ≥ +0.008.
- **맞으면**:
  - 이후 PubChem/게이트 계열 변경은 FL-replay 예측 Δ ≥ +0.004 (public 0.5분자)이고 bracket 양 끝이 모두 > 0 일 때만 제출한다.
  - DAILY "CV 통과" 정의를 "최종 단위 Δ" 로 바꾸자고 제안한다 (절대 규칙이라 사용자 확인 필요).
  - H2 로 간다.
- **틀리면**: PubChem 경로는 측정할 수 없는 영역으로 보고 건드리지 않는다. 점수 작업은 부품과 무관한 증거(H3)와 rank-1 arbiter(H4) 쪽으로 옮긴다.

### H2 (점수) PubChem 1위 승격 게이트를 덜 유명한 ② 분자에 맞게 다시 보정
- **가설**: 지금 게이트 `(S>6 & pop≥5) or rel>150` 은 유명 천연물 panel(249/250 COCONUT, 정답 pop 백분위 중앙 0.997)에서 골랐다. 그래서 덜 유명한 ②-PC 분자에서는 맞는 승격을 막고 있다. 채널 내부 증거(S, 채널 1·2위 margin, pop, rel, n_window, NP 플래그)로 보정한 게이트는 같은 오승격 비용에서 FL-replay 최종 MRR 을 +0.004 이상 올린다.
- **근거**:
  - 1위 결정은 전이율이 높다 (승격 도입 LB +0.024 이상, panel dbdrop 0.519→0.681).
  - panel 에서도 게이트 선택에 따른 차이가 크다: `S>5.5 & pop≥8 + early slots` 는 dbdrop 0.762 (+0.044), nospec 0.984 (−0.004) (results_merge_rules).
  - sim2 lib 정답의 lpmid 중앙은 0, lsid 중앙은 3.3 이다. npx 는 6.8 / 6.2 다 ([probe]). 덜 유명한 분자는 `pop≥5` 를 통과하기 어렵다.
- **메커니즘**: 정답이 pool 밖인 분자는 주 리스트 1위가 틀릴 수밖에 없다. 그러니 채널 1위가 맞을 확률이 0.5 를 넘는 순간부터 승격이 이득이다. 기대 이득은 대략 `P(채널 1위 정답) − P(주 1위 정답)·(1−1/2)` 이다. 이 확률은 유명도보다 margin 과 S 에 더 의존할 것이다.
- **예상 효과**: public +0.004~0.012 (분자 0.5~1.5개). 노이즈 안이라 LB 로는 확인할 수 없고 H1 판정에 의존한다.
- **가장 강한 반론**:
  - (A) 시나리오의 오승격 비용은 panel nospec(누수 있음, 유명 분자)으로만 잴 수 있다. p_main 을 모르기 때문에 게이트를 느슨하게 할수록 위험이 커진다.
  - 0.480 노트북에서 aggressive 해제는 −0.013 이었다. 느슨한 방향이 실제로 해로웠다는 직접 증거다.
  - ②-PC 비율이 6% 아래면 이득 상한이 0.005 아래로 떨어진다.
- **검증 방법**:
  - H1 의 sim2 v2 와 FL-replay 를 그대로 쓴다 (추가 Kaggle 비용 0). 로컬 4~5h.
  - 게이트 후보는 3개 이하로 미리 선언한다. 예: 로지스틱 P(채널 1위 정답) > 0.6, `S>6 & margin>m`, 현행.
  - identity fold 로 nested 선택하고, 혼합비·p_main sweep 전체에서 최소 이득을 본다.
- **채택/기각 기준**:
  - 채택: sweep 최악 경우에도 Δ ≥ 0, 중앙 추정 Δ ≥ +0.004, 오승격 수 증가가 (A) 에서 분자 1% 이하.
  - 기각: 중앙 Δ < +0.002, 또는 sweep 어디에서든 Δ < −0.002.
- **맞으면**: `kernels/sota0480` 복제본에서 게이트 한 줄만 바꿔 exp017 로 제출한다. 커널을 고칠 때는 `pc[0]` 판정 대상을 바꾸지 않도록 정렬은 공개 그대로 둔다. LB 는 −0.016 보다 크게 떨어지지만 않으면 유지한다.
- **틀리면**: 게이트는 현행으로 고정하고 PubChem 경로를 종료한다.

### H3 (점수, 직접 만든 데이터) 분자 단위 adduct·극성 프로파일로 같은 분자식 이성질체를 가른다
- **가설**: 한 분자에서 관측된 adduct 집합(예: [M-H]- 가 있는지, formate·Na·NH4 adduct, [M-H2O+H]+)과 양·음이온 base_peak_intensity 비율은 정답의 작용기(산성기, 염기성 질소, 폴리올·배당체, 탈수가 쉬운 OH)를 반영한다. Enveda timsTOF 데이터로 학습한 "구조 → 관측 프로파일" 확률 모델의 log-likelihood 를 fold-safe FP 점수에 더하면, 처음 보는 천연물의 같은 분자식 후보 안에서 top-1 이 +3%p 이상 오른다.
- **근거**:
  - [probe] enveda-np-examples 의 52% 가 양 극성 모두 측정됐다. 프로파일 분포는 [M+H]+ 단독 26%, [M+H]+|[M-H]- 22%, [M-H]- 단독 5%, Na 포함 11.6% 이상, formate 포함 3% 이상이다 (상위 프로파일만 합산). enveda-180(18.3만 분자, timsTOF) 은 양 극성 37% 다.
  - 오답의 98% 가 같은 분자식 이성질체다. pool 창 미학습 top1 0.42, top5 0.80 이라 2~5위에 정답이 38%p 몰려 있다.
  - 보이는 파이프라인 코드에서 `base_peak_intensity` 는 컬럼 목록에만 나오고, 분자 단위 adduct 집합 피처는 찾지 못했다. 엔진 패키지(v4g assets 안)는 보지 못했으니 **확인 필요**하다.
- **메커니즘**: 이온화 화학. 카복실산·페놀·황산기는 [M-H]- 가 강하고, 염기성 아민은 [M+H]+ 만 강하다. 중성 배당체·폴리올은 Na/NH4/formate adduct 를 잘 만든다. 같은 분자식이라도 산과 에스터, 아민과 아마이드는 프로파일이 다르다. 극성 간 강도 비율은 시료 농도가 약분되므로 농도에 영향받지 않는 이온화 효율 신호다.
- **예상 효과**: ②-pool(약 33~39%)에서 top-1 +3%p 이고 그 절반이 공개 융합을 통과하면 public +0.005 정도, +6%p 면 +0.01. 이것도 노이즈 안이라 H1/H4 경로로만 판정할 수 있다.
- **가장 강한 반론**:
  - 어떤 adduct 가 기록되는지는 구조보다 수집 정책(데이터 의존 획득, precursor 선택), 매트릭스, 농도에 더 좌우될 수 있다.
  - 같은 분자식 이성질체는 작용기 구성이 비슷한 경우가 많다 (배당 위치 이성질체 등). 그러면 판별력이 거의 없다.
  - enveda-180 은 합성 약물류이고 NP 는 npx 250 개뿐이라 학습 데이터 분포가 다르다.
  - 공개 엔진이 adduct 조건부 모델로 이미 간접 반영했을 수 있다.
  - 숨겨진 test 의 adduct 분포는 모른다 (보이는 test 는 train 예시).
- **검증 방법** (로컬 CPU 3~5h, GPU 0):
  - 데이터: enveda-180 + npx 분자, identity fold 5-fold. 라벨은 test 10종 adduct 안에서의 관측 집합(다중 라벨)과, 양 극성이 있을 때 log(bpi−/bpi+).
  - 모델: LightGBM, RDKit 기술자 + Morgan count.
  - 평가 (a): held-out 분자의 같은 분자식 후보 안에서 프로파일 log-lik 만으로 낸 MRR 을 무작위 기준선과 비교한다. 후보는 panel `main_candidates.parquet`(npx 250, pool 후보 포함)와 enveda-180 hold-out 의 train 구조 동일 분자식 이성질체를 쓴다.
  - 평가 (b): 같은 후보에서 fold-safe FP 점수 + w·loglik 로 top-1 이 어떻게 바뀌는지, paired bootstrap 으로 본다.
- **채택/기각 기준**:
  - 채택: (a) npx 에서 무작위 대비 MRR +0.05 이상, 그리고 (b) top-1 +3%p 이상이면서 95% CI 하한 > 0. enveda-180 hold-out 에서 악화가 없어야 한다.
  - 기각: (a) 가 무작위 대비 +0.02 미만.
- **맞으면**: H4 arbiter 의 피처로 넣는다. 단독으로 쓸 때는 최종 층의 1↔2 교체 규칙으로만 쓰고, H1 예측 Δ>0 일 때만 제출한다.
- **틀리면**: 기각을 기록하고 프로파일 방향을 닫는다. 비용이 작은 실험이었으므로 손실도 작다.

### H4 (점수) 1위·2위 교체 판정기(rank-1 arbiter): 최종 리스트 상위 3개 안에서 증거가 강할 때만 1위를 바꾼다
- **가설**: 같은 분자식 쌍(정답 vs 경쟁 후보)을 정직한 증거로 비교하는 pairwise 판정기를 만든다. 증거는 fold-safe FP 의 "두 후보가 다른 비트"에 대한 z, 파편 설명 강도 차, H3 프로파일, prior 차이다. 이 판정기를 최종 리스트 1위와 2~3위 사이에 **확신이 높을 때만** 적용하면(교체 정밀도 ≥ 0.65) 최종 MRR 이 오른다.
- **근거**:
  - 1위를 바꾸는 개입은 LB 로 전이됐다: fragment check leader move +0.005 (0.472→0.477), ICEBERG +0.013, GLACIER +0.006 (같은 분자식 그룹 재정렬, research/05 와 cell 43 주석).
  - 미학습 pool 창에서 top1 0.42 vs top5 0.80 이다.
  - MRR 구조상 2위 정답을 1위로 올리면 +0.5, 틀린 교체는 −0.5 이다. 그러니 정밀도가 0.5 를 넘으면 이득이다.
- **메커니즘**: 공개 1위는 RRF 로 섞은 순위가 정한다. 순위 융합은 "두 후보를 구분하는 비트·파편" 정보를 버린다. pairwise 비교는 바로 그 차이만 본다.
- **예상 효과**: 상위 3개 안에 정답이 있는 분자의 5~10% 를 정밀도 0.7 로 교체하면 public +0.004~0.01.
- **가장 강한 반론**:
  - **선택 효과**: 공개 1위가 틀린 분자는 공개 증거가 이미 실패한 어려운 분자다. 우리 증거도 거기서 가장 약할 가능성이 크다.
  - 9월에 우리 피처(prior, fpblock, frag2)는 자체 랭커에서 ≈0 이었다.
  - proxy 리스트(fold-safe FP + prior)의 1·2위 구성은 공개 리스트와 다르다.
  - 교체형 변경은 9월 3/3, 타인 2/2 가 LB 에서 손해였다. 단 그 사례들은 부품 전체 교체였고, 여기서는 일부 분자의 1위 교체다.
- **검증 방법**:
  - 로컬 8~12h, GPU 0~3h. 1차는 GPU 0: sim2 rows 와 `sim2_z.npy` 에 1619분자의 fold-safe z 와 후보가 이미 있다. panel `main_candidates` 는 pool 시나리오에 쓴다.
  - identity fold 로 학습·평가한다. 지표는 교체 정밀도와 coverage, 그리고 FL-replay 최종 Δ 다.
  - 학습 쌍이 부족하면 enveda-180 hold-out fold 의 fold-safe logits 를 Kaggle GPU 1~3h 로 만든다 (gpu_log 기록, 주 15h 안).
- **채택/기각 기준**:
  - 채택: NP 계열(npx + NP 라이브러리) hold-out 에서 교체 정밀도 ≥ 0.65, coverage ≥ 5%, FL-replay 예측 Δ ≥ +0.004 (bracket 양 끝 > 0).
  - 기각: 어떤 임계값에서도 정밀도 < 0.58.
- **맞으면**: 최종 층(cell 18 뒤)에 "1↔2 교체만" 하는 커널을 만들어 제출한다. 최종 2개 후보 중 하나로 둔다.
- **틀리면**: 1위 교체 계열을 종료한다. 남은 기간은 견고한 버전 선택(5절 계획)에 쓴다.
