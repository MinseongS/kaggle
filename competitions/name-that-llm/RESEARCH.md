## 공개 최고 파이프라인 (0.667) 구성
여러 사람이 이어 붙인 거대 앙상블이고, 제출 1회 재실행에 약 8시간이 걸림.
1. **LoRA24 멤버**: Qwen3-8B/14B, Qwen2.5-14B, Llama-3.1-8B
   - 앞쪽 약 2/3 레이어만 사용
   - 여러 중간 레이어의 hidden state를 mean pool
   - 분류 head는 plain과 prompt-centred 두 가지
   - 2단계 학습: (1) 외부 풀 약 120k~200k로 1 epoch → (2) 공식 train으로 2 epoch
2. **n-gram SVM, TF-IDF, distortion 멤버**: 공식 train과 외부 풀 데이터로 학습
3. **Gaussian 공유-프롬프트 head**: x = 저자 평균 + 프롬프트 효과 + 노이즈. 미지의 프롬프트에 대해 적분
4. **ATLAS** (Qwen3-8B 기반, 20%)와 complementary stack (15%)
5. **후처리**
   - Sinkhorn soft balancing (0.30): 예측 클래스 분포를 균등하게 맞춤
   - typography likelihood
   - sibling-style residual: 계열 안에서만 재정렬
   - pairwise verifier

## 핵심 교훈
1. **외부 데이터가 1순위 레버**

   - 정제 효과(쓰레기·장르 외 텍스트 제거)는 +0.027이고, `match_weight`(typography·길이 분포 맞춤)는 +0.026
   - train에는 we/our/us 같은 1인칭 복수 표현이 31%, 풀에는 15%. 호스트 프롬프트 스타일 차이로 보이고, **호스트 스타일에 맞춘 프롬프트로 생성하는 것이 다음 레버**라는 의견
   - gemini-3.7-flash는 2026-10-08 이후 Vertex 외 경로에서 3.8로 라우팅됨 → 라벨 오염
2. **규칙 (호스트 답변)**
   - 직접 생성한 데이터: 비공개로 써도 됨. 단 **총 비용 $5k(상금 1개분) 이내**
   - Kaggle Benchmarks proxy 쿼터로 학습 데이터를 만드는 것은 금지. 단, 그렇게 만들어진 공개 데이터셋은 사용 가능
   - Kaggle의 공개 데이터셋과 공개 LoRA 가중치는 사용 가능
   - 테스트 간 관계 활용(클러스터링, pseudo-label)은 아직 답변 없음
3. **테스트 구조: 프롬프트당 지문 수가 적음**
   - Hungarian이나 클러스터별 centering은 18개 전부 있는 CV에서는 +0.10이지만, **LB에서는 매번 -0.01~-0.02**
   - 반면 Sinkhorn(전역 클래스 균형)은 LB +0.011
4. **임베딩**: Qwen 초반 레이어(8% 깊이)가 마지막 레이어보다 저자 판별에 좋음 (0.39 vs 0.31). 스타일 정보는 앞쪽, 주제 정보는 뒤쪽에 있음
5. **앙상블은 다양성이 중요**: 같은 풀로 재학습한 더 강한 멤버(OOF +0.036)가 LB에서는 -0.004. 다른 데이터로 학습한 약한 멤버가 더 가치 있음
6. **짧은 지문이 어려움**: 60단어 이하 0.27, 160단어 이상 0.46. 잘라서 증강해도 효과 없음 (짧은 답은 원래 짧게 쓴 완결된 답이기 때문)

## LB 검증 전략 (노이즈)
- **같은 코드를 다시 제출해도 public 점수가 최대 0.009 흔들림** (ATLAS 시간 예산 등 비결정성)
- 두 제출의 차이에 대한 표준편차 ≈ sqrt(f / 1200). f는 두 모델 중 한쪽만 맞힌 행의 비율
  - f=5% → 0.006, f=10% → 0.009, f=20% → 0.013
  - f는 OOF에서 미리 계산 가능
- **grouped CV와 LB의 관계**
  - train만으로 학습한 모델: CV ≈ LB (±0.01)
  - 외부 풀로 학습한 모델: **CV가 LB보다 0.03~0.04 높게 나옴**. 풀 모델끼리만 비교해야 함
- **프롬프트 의존 단계**(centering, Sinkhorn 등)는 OOF를 "프롬프트당 2개(m=2)"로 잘라서 평가
  - LB와의 상관이 0.91로, 18개 전부 쓸 때(0.13)보다 훨씬 높음
  - 다만 15개 제출 기준이라 약한 신호. 나쁜 설정을 걸러내는 용도로만 사용
- 하루 제출 수가 제한되므로 LB는 큰 변화(>0.01)만 확인하는 용도로 씀
