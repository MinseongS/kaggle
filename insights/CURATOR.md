# 인사이트 큐레이터 지시 (주 1회 자동 실행)

목표: `common.md` 와 `playbooks/*.md` 를 **모델이 원래 알지 못하는, 근거 있는, 조건이 명확한** 항목만 남은 짧은 문서로 유지한다. 대회 세션은 `PROTOCOL.md` 를 따른다.

## 항목 형식
```
- [I-xx] 조건: <어떤 대회/상황> | 행동: <무엇을 한다> | 근거: <대회, exp id, CV/LB 변화> | 확인: N (<slug들>) | 반례: <없음 또는 내용> | 등록: YYYY-MM-DD | 최근 사용: YYYY-MM-DD
```
- 근거가 "외부 통념 (미검증)"인 확인 0 항목은 초기 시드로만 허용한다. 새로 받지는 않는다.
- ID는 영구다. 삭제해도 번호를 재사용하지 않는다. 다음 번호는 `INDEX.md` 에 적힌 값을 쓴다.
- 조건을 쓸 수 없는 항목(늘 맞는 일반론)은 받지 않는다.

## 신뢰도 단계와 위치
| 단계 | 기준 | 위치 |
|---|---|---|
| 후보 | 확인 0~1 | 해당 `playbooks/<type>.md` 의 `## 후보` 절. 유형을 넘는 것은 `common.md` 의 `## 후보` 절 |
| 확정 | 2개 이상 대회에서 확인, 반례 없음(또는 조건으로 해소) | playbook 본문. 유형을 넘으면 `common.md` |
| 축소·강등 | 반례 | 조건을 좁히거나 후보로 내린다. 조건으로 설명이 안 되면 삭제 |

- 예외: CV로 판정할 수 없는 운영·인프라 항목(대기열, 제출 형식, 토큰 등)은 실제로 겪은 근거가 있으면 확인 1이어도 확정에 둘 수 있다.

## 상한
- `common.md` 확정 15개 + 후보 10개, playbook 하나당 확정 10개 + 후보 10개. 넘으면 가장 약한 것(확인 수 적음, 오래 안 쓰임)을 뺀다.
- `## 참조` 절(메달 기준 같은 사실 정보)은 항목 형식·상한에서 제외하되 5줄 이내.

## 매 실행 절차
1. `inbox/*.md` 에서 지난 실행 이후 추가된 줄(`INDEX.md` 의 "마지막 처리" 이후)을 모은다.
2. `used` 줄: 해당 항목의 확인 수·반례·최근 사용일을 갱신하고, 단계를 올리거나 내린다.
3. `new` 줄: **입장 테스트**를 한다. 인사이트 파일을 읽지 않은 서브에이전트(Agent 도구)에게 그 상황만 주고 "기본으로 어떻게 하겠는가"를 묻는다. 이미 그 행동을 한다면 받지 않는다 (가치 0). 근거 수치가 없으면 받지 않는다. 통과하면 후보로 넣는다. 같은 내용의 기존 항목이 있으면 확인 수만 올린다.
4. **퇴출**: 최근 사용이 6주보다 오래된 후보는 삭제, 확정은 후보로 강등. (최근 사용이 비어 있으면 등록일 기준.)
5. 대회 간 **운영 메커니즘 중복**을 본다: 두 대회 이상에서 같은 역할의 코드(제출 큐, 자동 제출, healthcheck, 토큰 점검 등)가 있으면 `INDEX.md` 의 "공통화 후보"에 적는다. 직접 옮기지는 않는다 (사람이 결정).
6. 종료된 대회(README 마감일 경과)에 `postmortems/<slug>.md` 가 없으면 `INDEX.md` 의 "사람 할 일"에 적는다.
7. `INDEX.md` 를 갱신한다: 마지막 처리 시각, 다음 ID, 이번 변경 요약(추가/승격/강등/삭제 각 ID와 이유).
8. git 커밋은 하지 않는다 (사용자가 요청할 때만). `insights/` 밖의 파일은 고치지 않는다.
9. 마지막 메시지에 변경 요약을 한국어 5줄 이내로 남긴다.

## 첫 실행 (INDEX.md 의 "마지막 처리" 가 비어 있을 때) 추가 작업
각 대회 폴더(`competitions/*/`)의 `EXPERIMENTS.md`, `HYPOTHESES.md`(검증 로그), `insights/`·postmortem, 회고(`outputs/daily/retro-*`)를 훑어 **이미 검증된** 대회 간 교훈을 `new` 후보로 뽑고, 3단계와 같은 기준(입장 테스트·근거·조건)으로 처리한다. 대회 고유 지식은 넣지 않는다.
